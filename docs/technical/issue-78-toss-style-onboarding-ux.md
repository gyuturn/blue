# 토스식 온보딩 UX로 청약 가점 계산 개편

**Issue:** [#78] 토스 스타일 온보딩 가이드 UX로 청약 가점 계산 개편
**Date:** 2026-09-27
**Status:** Implemented

---

## 1. 원칙

1. **한 화면에 질문 하나** — 제목 자체가 질문 ("지금 내 집이 있나요?")
2. **쉬운 말 먼저, 규칙은 펼쳐서** — 기본 문구에 전문 용어를 쓰지 않고, 규칙은 "왜 물어보나요?"(`<details>`)에
3. **버튼은 하나, 엄지 닿는 곳에** — 하단 고정 CTA, 뒤로가기는 상단 화살표
4. **바로바로 반응** — 답할 때마다 "지금까지 예상 점수" 갱신

비주얼(색·폰트·라운드)은 #80에서 고른 디자인으로 교체한다. 이번 변경은 흐름·문구·레이아웃만 다룬다.

## 2. 흐름 변경

| 이전 (5단계) | 이후 (6단계) |
|---|---|
| 무주택 → 부양가족 → 청약통장 → 거주지역 → 혼인/자녀 | 집 → **결혼** → 가족 → 청약통장 → 사는 곳 → 자녀 |

**결혼을 2단계로 앞당긴 이유:** 무주택 기간 시작일은 "만 30세 생일"과 "혼인신고일" 중 빠른 날이다. 이전에는 결혼을 마지막에 물어서 1단계에서 보여준 무주택 점수가 5단계에서 바뀌었다(예: 만 30세 미만 기혼자는 1단계에서 "기간이 쌓이지 않아요"를 봄). 입력 필드(`EligibilityInput`)와 계산 로직은 그대로다.

## 3. 점수 단일 출처

- 계산기의 모든 미리보기 점수는 `calculateTotalScore(input)`의 항목 점수를 그대로 쓴다. 이전 1단계 미리보기는 `homelessYearsFloor <= 0 ? 2 : …`로 계산 규칙을 복제하고 있었다.
- "지금까지 예상": 1~2단계 무주택 / 3단계 +부양가족 / 4단계 이후 총점. 5~6단계는 "점수와 상관없어요 · 특별공급 확인용".
- 결과 화면의 "점수 올리는 법" 문구는 숫자 대신 규칙 설명만 쓴다(#82 점수표 수정 전후 모두 참인 문장).

## 4. 화면별 변경

- **홈** (`app/page.tsx`): 헤드라인 "내 청약 점수, 1분이면 알 수 있어요", "이렇게 계산해요" 3줄(항목별 최대 점수), 하단 고정 CTA "내 점수 알아보기" + "로그인 없이 바로 시작해요". 저장된 점수 카드(#79)는 맨 위.
- **계산기** (`app/calculator/page.tsx`): 상단 얇은 진행바(`StepIndicator` 교체), 질문형 제목, 선택 카드(`ChoiceCard`), "왜 물어보나요?", 단계 전환 애니메이션(`animate-fade-slide-in`), 하단 고정 CTA + 예상 점수. 청약통장 단계에서 납입 횟수·예치금은 "점수에 들어가지 않아요"로 부담을 낮춤.
- **결과** (`app/result/page.tsx`): "내 청약 가점은" → 숫자 카운트업(`useCountUp`, `prefers-reduced-motion`이면 즉시 표시) → 등급 뱃지 + 해석. 항목마다 "왜 이 점수인지"(예: "혼인신고 날짜가 없어 기간을 셀 수 없었어요")와 "점수 올리는 법". 하단 고정 CTA "내 점수로 청약 공고 보기".
- **헤더**: 메뉴 간격 축소, "자격계산기" → "점수 계산".

## 5. 접근성

- 선택 카드 `aria-pressed`, 진행바 `role="progressbar"` + `aria-valuenow`, 예상 점수 `aria-live="polite"`, 결과 숫자는 카운트업 중에도 `aria-label`에 최종 점수.
- 애니메이션은 `prefers-reduced-motion: reduce`에서 끔.
- 하단 고정 영역은 `env(safe-area-inset-bottom)` 여백.
