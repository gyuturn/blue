# 청약 가점표 정확도 수정

**Issue:** [#82] 무주택기간·청약통장 가입기간 점수표가 법정 기준과 1구간씩 어긋남
**Date:** 2026-09-27
**Status:** Implemented

---

## 1. 기준 (주택공급에 관한 규칙 별표1)

| 항목 | 법정 기준 | 이전 코드 | 수정 후 |
|---|---|---|---|
| 무주택기간 | 1년 미만 2점, 1년마다 +2, 15년 이상 32점 | `floor(년)×2` (1년 = 2점, 16년에 32점) | `min((floor(년)+1)×2, 32)` |
| 청약통장 가입기간 | 6개월 미만 1, 6개월~1년 미만 2, 1년 이상 `년수+2`, 15년 이상 17점 | `floor(년)×2+1` (8년에 17점) | `subscriptionScoreFromMonths` |
| 부양가족 | 0명 5점 ~ 6명 이상 35점 | 정확 | 변경 없음 |
| 신혼부부·다자녀 특별공급 | 무주택 세대 조건 | 무주택 조건 없음 | `isHomeless` 조건 추가 |

## 2. 구현

- `calculateHomelessScore(years)`: 음수는 0으로 보고 `min((floor(years)+1)*2, 32)`.
- `calcHomelessYearsFromPolicy`: 입력이 `YYYY-MM`이므로 일수(365.25) 대신 **개월 수 / 12**로 계산한다. 기념일 경계에서 0.9993년처럼 소수점 오차로 한 구간 낮게 나오는 문제를 없앤다.
- `calculateSubscriptionScore(startDate, now?)`: 개월 수를 구해 `subscriptionScoreFromMonths(months)`로 변환한다. 가입일이 없거나 미래면 1점.
- `calculateSpecialSupply`: 신혼부부·다자녀에도 `input.isHomeless` 조건.
- 결과 화면 특별공급 설명: 유주택자에게는 "집이 없는 세대만 신청할 수 있어요"를 보여준다.

## 3. 데이터 영향

- localStorage와 DB에는 입력값(`inputSnapshot`)이 저장되고 화면은 읽을 때 다시 계산한다(#79). 마이그레이션은 필요 없다.
- DB `subscription_scores`의 점수 컬럼은 과거 기준 값으로 남는다. 현재 화면은 이 컬럼을 읽지 않는다.

## 4. 검증

경계값 38건을 법정 표와 비교해 모두 일치했다(무주택 0/0.99/1/1.99/2/10.3/13.99/14/14.99/15/20년, 통장 0/5/6/11/12/23/24/42/96/167/168/179/180/300/−3개월, 날짜 입력 5건, 특별공급 유·무주택 6건, 혼인 정확히 11년 경계). 앱 화면에서 계산기·결과·홈 카드 점수 일치(56점)도 확인했다.

## 5. 이번에 바꾸지 않은 것 (확인 필요)

- **만 30세 미만 미혼 무주택자**: 현재 무주택 점수 0점. 무주택기간을 0으로 보고 "1년 미만 2점"을 줘야 한다는 해석이 있다.
- **다자녀 기준**: 현재 미성년 자녀 3명 이상. 2024년 개정으로 2명 이상으로 완화됐다는 정보가 있어 법령 원문 확인이 필요하다.
- 테스트 러너가 없어 검증은 스크립트로 했다. 회귀 방지를 위해 vitest 도입을 제안한다.
