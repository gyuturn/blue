# 로그인 사용자 메인 = 공고목록 설계

**Issue:** [#111] 로그인 + 저장된 점수가 있으면 메인을 공고목록으로
**Date:** 2026-10-12
**Status:** Implemented

## 1. 문제
점수를 계정에 저장한 사용자도 `/`에서 "내 점수 알아보기" 소개 화면을 본다. 이들에게 필요한 건 공고목록이다.

## 2. 결정: 서버 컴포넌트에서 `redirect('/announcements')`

`app/page.tsx`는 이미 세션과 계정 최신 점수(`getLatestServerRecord`)를 서버에서 조회한다.
그 결과로 판정해 `next/navigation`의 `redirect()`를 호출한다.

| 대안 | 채택 여부 | 이유 |
|------|-----------|------|
| 서버 컴포넌트 `redirect()` | ✅ | 추가 쿼리 없음, 화면 깜빡임 없음, URL이 `/announcements`로 바뀌어 새로고침/공유 일관 |
| middleware에서 리다이렉트 | ❌ | middleware(Edge)에서 DB 조회 필요 → 모든 요청 지연 |
| 클라이언트 `router.replace` | ❌ | 메인이 잠깐 보였다가 이동 (깜빡임) |
| `/`에서 공고목록 컴포넌트 직접 렌더 | ❌ | 773줄 클라이언트 페이지 분리 필요, URL 이중화 |

## 3. 판정 규칙 (`lib/home.ts` → `shouldShowAnnouncementsAsHome`)
- 로그인 **AND** 조회 성공 **AND** 계정 기록 존재 → 공고목록
- 조회 실패(`ok: false`)는 점수 유무를 모르므로 기존 메인 (안전한 기본값)
- 의존성 없는 순수 함수로 분리해 `node --test`로 단위 테스트 (`tests/home.test.ts`)

## 4. 영향 / 트레이드오프
- 공고목록은 이미 `/api/scores/latest`로 계정 점수를 불러와 요약 바를 보여주므로 추가 변경 없음.
- 기기에만 있는 더 최신 점수의 "계정에 저장할까요?" 제안(`LastScoreCard`)은 메인에서만 뜨므로,
  계정 점수가 이미 있는 사용자에게는 더 이상 보이지 않는다. 공고목록은 기기/계정 중 최신 점수를 사용하므로
  표시 점수는 정확하고, 다음 계산 시(로그인 상태) 계정에 저장된다.
- 비로그인 사용자의 기기 저장 점수 카드는 그대로 유지.
